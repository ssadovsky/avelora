# Герои: как добавлять персонажей, упрощать модель, делать хваты и позы верхом

Единый справочник для людей и агентов (Claude, Codex, Antigravity/Gemini). Описывает то, что уже сделано и проверено на Маге, Чародейке и Лучнице. Правила общего характера (serverless `file://`, политика тестов, цвета) остаются в `CLAUDE.md` / `GEMINI.md`; здесь только персонажи.

**Главное правило тестов.** Агент не может открыть игру (`file://`). Он проверяет модель рендерами и загрузкой в three.js (`load_check.js`), а в игре смотрит пользователь. Не писать «работает», пока пользователь не проверил: писать «в игре не проверено».
**Git.** Не коммитить и не откатывать, пока пользователь явно не попросил. `temp_work/` в git не входит (он на диске пользователя), поэтому всё, что нужно агентам, — здесь и в `temp_work/rig/tools/README.md`.

## 2. Добавить героя (пошагово)

1. **Исходник.** Meshy: модель + риг + анимации Mixamo в одном GLB (положить в `temp_work/lib/3d/…`). Проверить: число костей, имена (`mixamorig:*`), клипы, исходный рост (~1.7 м), ширина плеч, высота сустава бедра (см. §4).
2. **Упростить сетку** (§3) → `lite_a.glb`. Обычно 55–80 тыс. треугольников (Маг 58k, Чародейка 75k, Sovereign 79k).
3. **Собрать модель** (§4): свои Idle/Cast/Greeting, исправление поз, 1K-текстуры, пересборка бинарного блока. Образец — `temp_work/rig/tools/build_mage_template.py`. Результат в `models/characters/<Имя>/<Имя>.glb`.
4. **Подключить ассет.** В `temp_work/build_assets.py` в словаре моделей: `'ключ': file_to_b64('models/characters/<Имя>/<Имя>.glb')`. Запустить `python3 temp_work/build_assets.py` (или `build_assets.bat`).
5. **Каталог** (`js/characters.js`): для нового класса — запись в `CHARACTER_CATALOG`; для нового пола существующего класса — элемент `genders[]` с `preview` и `overrides` (§5). Иконка героя: файл `temp_work/lib/hero_portrait_<имя>.jpg`, ключ `heroPortrait_<имя>` в `build_assets.py`, поле `portrait` в overrides.
6. **Хват, поза верхом, цвет** (§6, §7, §8).
7. **Версии кэша.** Поднять `?v=` у изменённых скриптов в `Avelora.html` и `CACHE_NAME` в `js/sw.js` (иначе браузер и сервис-воркер покажут старое).
8. **Проверка** (§9) и запись итога в проектный документ (Claude Project «Avelora»: `claude/avelora_<тема>_<дата>.md`).

## 2a. Авториг: меш без рига → готовый герой одной командой (`hero_pack.py`)

Когда: у Meshy риг по ориентирам получается один раз из трёх, а исправления после него (плечи, кисти, бёдра, торс) съедают много времени. Тогда из Meshy берём **только меш + текстуры** (без рига, без анимаций), скелет, веса и клипы даёт инструмент. Проверено на Crimson Vanguard (муж и жен) и Forest Sentinel.

```
python3 temp_work/rig/tools/hero_pack.py models/characters/EmeraldRanger/EmeraldRanger.glb <меш_без_рига.glb> <результат.glb>
```
Шаблон (первый аргумент) — готовый герой с ригом Mixamo из 66 костей; его скелет, сетка и 12 клипов (Idle, Running, Walking, Boxing_Practice, танцы и т. д.) переносятся на новый меш. Другие шаблоны (женский, четвероногий, ракообразные, антропоморфные вроде Малакара) пока не делались: для них нужен свой готовый образец.

**Что происходит (`hero_pack.py` → `hero_autorig.py`):**
1. Упрощение `lighten.mjs` до `--tris` (по умолчанию 85 000), голова защищена (box по росту модели, 90% треугольников). Нужен `npm install` в `/tmp/lh` (скрипт делает сам из `temp_work/lighten`). `--no-simplify` пропускает шаг.
2. Меш приводится к кадру шаблона (рост `--height` 1.7 м, ступни на y=0, по центру). `--flip` — если модель смотрит назад.
3. Скелет шаблона подгоняется под меш поворотами Arm, ForeArm, Hand, UpLeg (перебор углов по расстоянию до меша, без изменения длин костей).
4. Веса: сетка шаблона в подогнанной позе → перенос с ближайших вершин (k=4), смешивание левой/правой стороны (юбки, фартуки), сглаживание по сварной сетке, не больше 4 влияний на вершину.
5. Клипы шаблона переносятся в локальных осях с поправкой на подгонку. По умолчанию руки не трогаются. Опция `--arm-out Idle:плечо[:кисть]` в клипе Idle отводит плечо и кисть от тела на заданные градусы (несколько клипов через запятую). **Поправка зависит от меша, подбирать по рендеру и по строке самопроверки**, которую печатает `hero_autorig.py`: углы левой руки в Idle от вертикали (эталон Изумрудного лучника: плечо 10.9°, предплечье 9.5°, кисть 7.2°, кисть по x 0.242 м). Воину (руки висели вплотную, пальцы внутрь) нужно `Idle:8:16`; Forest Sentinel без поправки сразу даёт 10.9 / 9.0 / 6.7 (с `8:16` руки разводились слишком широко).
6. `--skin-tint [сила]` — тон кожи как у старых героев (docs «skin_tint»: маска кожи по цвету, цель ≈(199,116,90), множители зажаты в [0.62, 1.0], сила 1.0 = полный тон, степень множителей). В игре холодный свет делает кожу бледной; у Forest Sentinel нужен `--skin-tint 0.6` (полный тон на рендере оранжевый рядом с мужчиной-лучником). Печатает среднюю кожу и множители.
6a. `--robe [доля]` + `--no-fit` — длинное платье/мантия (проверено на Лираэли, Sapphire Enchantress, 2.1M тр.): ниже бёдер часть веса ног передаётся тазу (подол следует тазу), вес ног остаётся только у вершин рядом со ступнями шаблона (сапоги); усиленная диффузия весов по сетке (12 итераций, рукава-колокола). `--no-fit` нужен, если широкие рукава сбивают подгонку рук (без него плечо −21°). Результат Лираэли: `--robe 0.8 --no-fit`, Walking p99.5 3.0 и 2.4% рёбер >1.5× (без `--robe` 14.1 и 4.7%). Голову при 2M тр. защищать ratio 0.1 (бокс головы захватывает капюшон и волосы: 370k тр.), тело 0.036 → 100k тр.
7. Текстуры до 1K (`--tex`), запись GLB, метрика растяжения рёбер на 4 клипах, рендер поз `<результат>_poses.png`, `load_check.js`.

**Критерии качества:** на клипах Running/Walking/Agree_Gesture/Boxing_Practice доля рёбер, растянутых >1.5×, должна быть ≈1–3%, p99.5 растяжения ≈2 или меньше (у проверенных: 0.5–2.9%). Обязательно посмотреть `_poses.png` и крупный рендер кистей в Idle (у воина 16° для кисти подобрано рендером: 28° уже перебор).

**После hero_pack** — те же шаги, что в §2 (4–8): ассет в `build_assets.py`, запись в `CHARACTER_CATALOG` (`genders[].preview/overrides`), версии кэша. Особенности авториг-героев:
- Хват и пальцы можно взять у героя-шаблона (`handGrip`, `gripFingers`, `itemHoldKey: 'emeraldRanger'`, `bowDrawHold`, `bowCarryUpright`, `bowPullKeys`): риг один, но кисти подогнаны по мешу, поэтому **в игре проверять**; если хват «плывёт» — `grip_solve.py` + `tool_grip_render.py` (§6.4).
- Картинки меню: иконки пола `icons/charcreate/cs_<…>.png` (≈280×300, прозрачный фон), эмблема класса (≈279×277 с полями), портрет 512×512 jpg для `heroPortrait_<ключ>` в `build_assets.py` (вырезается из листа «профиль.jpg» по панелям). Размер эмблемы на экране создания задаётся CSS `.cs-class-card[data-class-id=…] .cs-emblem img` (у лучника 100px, у воина 102px), в списке слотов — файлом иконки (см. `.cs-slot-icon-box.has-emblem` и условие по `classId` в `main.js`).
- Класс без `content/characters/<id>/skills.json` играбелен только с базовой атакой.

**Ограничения (не сделано):** суставы не уточняются по сечениям меша; меш в T-позе не приводится к A-позе шаблона; Cast/Greeting и свои Idle (как у Мага) не строятся; хват не вычисляется автоматически.

## 3. Упрощение модели без порчи лица, деталей и цвета

Инструмент: `node temp_work/lighten/lighten.mjs --job job.json` (meshoptimizer `simplifyWithAttributes`: учитывает UV, нормали, вершинные цвета и веса скина). Node 20+, `npm install` в `temp_work/lighten` (папка `node_modules` собрана под Windows; на Linux делать `npm install` в копии).

Формат задачи (проверено на Маге, Чародейке, Sovereign):
```json
[["orig.glb", "lite_a.glb", {"*": {
  "ratio": 0.65, "err": 0.005, "lockBorder": true,
  "regions": [{"box": [-0.14, 1.45, -0.14, 0.14, 1.72, 0.20], "ratio": 0.9}]
}}]]
```
- `ratio` — доля оставляемых треугольников для всего материала (герой: 0.3–0.7 по тому, сколько исходник; цель 55–80k).
- `regions[].box` = `[minX,minY,minZ,maxX,maxY,maxZ]` в единицах GLB, ratio для лица и головы 0.85–0.9. Бокс головы для модели ростом 1.7 м: `[-0.14,1.45,-0.14, 0.14,1.72,0.20]` (подтвердить по рендеру). Кисти/тонкую ткань/узоры можно защитить такими же регионами.
- `lockBorder: true` обязателен (иначе дыры по швам UV и расходятся юбки).
- Исходник не перезаписывать (писать в `lite_*.glb`).

**Что нельзя.**
- Не гнать лёгкую модель через trimesh/seamfix/prune: ломает скин и порядок костей (для скинованных мешей).
- Не перекрашивать текстуру ради «яркости»: цвет героя = пиксели исходника. Текстуры только уменьшаем (1024×1024 JPEG q90–93, `LANCZOS`), ничего не пережигаем. Исключения (всё явно записывать): цветовая маска для тона кожи (Чародейка ×0.92/0.83/0.74), закраска дефектов по маске UV (спина Мага), `liftNavyFabric` в коде.
- Не удалять анимации/кости; не менять индексы суставов.

**Проверка результата (обязательно, до сборки героя):** рендер оригинала и lite с 3–4 сторон крупно (лицо, грудь/узоры, низ халата, кисти), сравнить; искать дыры, рваные края, потерянные тонкие детали (`temp_work/rig/tools/pose_montage.py`).

## 4. Сборка модели героя (риг, анимации, пропорции)

Всё чистым python без Blender: `temp_work/rig/tools/sorc_tools.py` (`load_glb/save_glb`, `Rig`, `mesh_arrays/skin`, `raster/montage`) + `build_mage_template.py` (параметры `ARM CLAV ELBOW TWIST TORSO_K`).

**Что делает сборка.**
- Свои клипы `Idle` (60 кадров, дыхание) и `Cast` (24 кадра; пик на кадре 9–13 = 0.3–0.43 с, это время `channelHoldTime` 0.4), `Greeting` из `Agree_Gesture`; остальные (`Running`, `Walking`, `Dead`, танцы) берутся из Meshy-клипов как есть. Имена клипов должны совпасть с теми, что ждёт `animMap` (§5): Idle, Running, Walking, Cast, Greeting, Dead, `Boxing` (удар кулаком без оружия).
- **Idle строить от позы покоя, а не из `Agree_Gesture`:** в Mixamo-клипах (`Agree_Gesture`, `Boxing_Practice`) плечи сужены (ширина плеч 0.28 м вместо ~0.36–0.38). Greeting чинится перенормировкой ключиц: `R_arm' = R_clav'⁻¹ · R_clav · R_arm`.
- **Кости Hips: yaw в Idle всегда 0°** (иначе «бег задом»; см. `GEMINI.md` §4). Не выгибать корпус назад.
- **Руки в покое у Meshy уже в A-позе (~61–65° вниз):** доворот рук небольшой (`ARM 16, CLAV 0, ELBOW 10`). Первая попытка доворота на 64° сложила руки к плечам.
- **Ладони смотрят вперёд** в исходных клипах → скрутка предплечья и кисти вокруг своей оси на `TWIST` (~80°, поровну на предплечье и кисть) во **всех** клипах: ладони к бёдрам.
- **Текстуры** → 1024² JPEG, бинарный блок пересобирается (без старых анимаций, без неиспользуемых accessor'ов).

**Пропорции (целевые, по старому Магу; измерять `Rig` в позе покоя):**

| | старый Маг (Mixamo) | цель |
|---|---|---|
| рост | 1.70 м | 1.70 |
| сустав бедра (UpLeg) | 0.853 м = 50% роста | 47–50% |
| бедро (UpLeg→Leg) | 0.365 | 0.33–0.37 |
| голень | 0.366 | ~0.36 |
| кость таза → шея | 0.44 | ≤0.46 |
| ширина плеч (Arm–Arm) | 0.353 | 0.35–0.38 |

Meshy-риг по умолчанию сажает сустав бедра ниже, а торс получается длиннее на 6–7 см. Этому соответствует «непропорциональный» вид на экране выбора и верхом. Что делать:
- **В Meshy** («Применить риг к модели»): маркер «Пах» (groin = промежность, не пупок) поднимать так, чтобы сустав бедра вышел на ~50% роста. Маркер на ~55% роста дал сустав на 47% (Sovereign), на ~47% — 44% (Oathkeeper). После нового риггинга **измерить** (сустав бедра, бедро, торс) и сверить с таблицей, а не оценивать на глаз по скрину.
- **В сборке:** `TORSO_K` (0.88) сжимает цепочку `Spine, Spine1, Spine2, Neck` (translation в узлах и в каналах клипов) → торс короче на ~12%, рост вернуть `scale` (1.09). Работает без разрывов на халате (проверено рендерами), но это компромисс: лучше исправить в Meshy.

**Рендеры позы (не пропускать):** Idle спереди/сбоку, Cast, Greeting, Walking, Running сбоку. Искать: сузившиеся плечи, пересечение халата с ногами, провалы, перекрутку кистей.

## 5. Конфиг героя (`js/characters.js`)

Базовые поля записи класса (`CHARACTER_CATALOG[i]`), для пола — те же ключи в `genders[].overrides` (склеиваются `resolveCharacterConfig(cfg, genderId)`):

| ключ | значение |
|---|---|
| `modelKey` | ключ ассета (`build_assets.py`) |
| `animMap` | `{idle, run, greeting, cast, unarmed?, attack?}` → имена клипов; `unarmed` играется только когда в руке пусто; без `attack` используется процедурный взмах |
| `scale`, `facingOffset` | масштаб модели (Маг 1.05), `facingOffset: Math.PI` (лицом вперёд) |
| `noNavyLift` | отключить осветление тёмно-синей ткани (для всех, кроме старого Мага) |
| `portrait` | `heroPortrait_<имя>` |
| `channelHoldTime` | секунды позы каста при долгих заклинаниях |
| `handGrip` | `{position[м], rotation[рад XYZ]}` — «держатель» предмета в системе кости правой кисти; **общий для ВСЕХ предметов** (топор, кирка, лук…), под один предмет не подгонять (§6.4); для посоха с `staffGrip` не нужен |
| `itemHoldKey` | ключ в `item.json → hold.<ключ>` для этого героя (если задан, вместо id класса); у каждого лука/посоха должен быть `hold.<ключ>` (§6.4) |
| `bowDrawHold` | `[rx,ry,rz]` — поза лука в кисти при натяжении (§6.4 п.5); без него запястье гнётся ~90° и кисть деформируется |
| `bowCarryUpright`, `bowCarryTilt` | `true` — на бегу лук доворачивается кистью до вертикали с наклоном верха вперёд (`bowCarryTilt`, градусы, по умолчанию 10); работает и в покое, и на ходу; иначе клип бега тянет его наискось через корпус |
| `bowPullKeys`, `bowDrawToFace` | оттяжка тетивы левой рукой (кривая `[[t, угол°],…]`) и подтяжка левого предплечья к голове (§6.4) |
| `staffGrip` | `{position[м], axis}` — точка и ось древка посоха в системе кости кисти (§6) |
| `gripFingers` | кватернионы пальцев правой кисти при хвате `{"RightHandIndex1":[x,y,z,w], …}` (§6) |
| `riderPose` | поза верхом (§7); поверх `RIDER_POSE` в `character.js` |
| `preview` (только в `genders[]`) | `{modelKey, faceAngle, scale, idle}` — витрина экрана выбора |

## 6. Хваты: посох, лук, оружие

Общее: предмет в руке — «держатель» (`holder`) на кости `RightHand`; `applyGrip` включает хват плавно (≈0.1 с), когда в руке что-то есть (`handItem` видим), и выключает без предмета. Без предмета кисть остаётся открытой, как исходная.

### 6.1 Способ A — пальцы-кости (риг с пальцами: Чародейка, Meshy-герои)
- `gripFingers` — локальные кватернионы костей `RightHandThumb1..3, Index1..3, Middle1..3, Ring1..3, Pinky1..3` (без `*4`). Применяются после `mixer.update`, имена без префикса `mixamorig:`.
- Получить сгиб: для каждой кости `slerp(rest, Agree_Gesture[0], K)` с **экстраполяцией** K≈2.2 (поза Agree — расслабленная ладонь; ×2.2 даёт сжатый кулак). `rest` брать из **собранной** модели, а не из исходника (ориентации костей кисти различаются между моделями Meshy; перенос кватернионов с одной модели на другую даёт растопыренные пальцы).
- `staffGrip`: `python3 temp_work/rig/tools/grip_cavity.py K model.glb original.glb out.json` — ось = линия костяшек `Index1→Pinky1` в системе кисти, центр = пустая полость в срезах кулака (площадь 5–15 см²). Затем сдвинуть центр по y к кончикам пальцев (на +0.01…0.02), чтобы посох оказался внутри согнутых пальцев, а не над костяшками. Проверка: `grip_staff_render.py "[x,y,z]" "[ax,ay,az]" out.png model.glb out.json` (цилиндр r=1.6 см; посох виден внутри согнутых пальцев спереди, не позади кисти и не поверх). Знак оси брать так, как у существующих героев (положительный z в системе кисти).
- Примеры значений: Чародейка `staffGrip {position:[-0.008,0.080,-0.014], axis:[-0.2,0.14,0.97]}`; Sovereign `{[0.005,0.087,0.011], [0.309,0.329,0.892]}` (подобрано, но модель откатили).

### 6.2 Способ B — кулак как morph-target `grip` (риг без пальцев: старый Маг)
- Кости пальцев отсутствуют (только `RightHand` и `RightHandMiddle4`). Кулак — смещение вершин кисти в morph-target `grip` (позиции и нормали, разрежено ~1.4k вершин); база меша — открытая кисть.
- Сборка: `python3 temp_work/rig/tools/build_grip_morph.py fist.glb open.glb out.glb` (`fist` — версия с запечённым кулаком, `open` — версия до запекания с теми же вершинами; разница даёт delta). Исходный запекатель кулака — `temp_work/mage_grip/fist.py` (загибает вершины правой кисти за костяшками на 80° + 75°).
- В коде `applyGrip` выставляет `morphTargetInfluences[grip] = gripW` для всех мешей с таким morph (`_gripMorphs`, `character.js?v=grip4`). Проверка загрузки: `node temp_work/rig/tools/load_check.js <glb>` — должно быть `morph: {"grip":0}`.
- `staffGrip` у такого героя остаётся прежним (форма кулака та же).

### 6.3 Посох (`style: 'staff'`, предмет с `userData.upright`)
- При `staffGrip` предмет ставится по точке и оси, `item.json → hold` игнорируется. Посох **всегда вертикален** (наклон вперёд ~8°), кисть доворачивается (`applyCarryUpright`). Каст и удар посохом = обычный каст (рука вперёд-вверх, `aimBoneWorld`). Верхом вне каста посох лежит поперёк седла (наклон влево, центруется по середине древка).
- Без `staffGrip` — старое крепление `handGrip + hold`, посох вертикален только на ходу.

### 6.4 Лук, топор, кирка и любой предмет в руке (проверено на Emerald Ranger, 2026-11-23)

**Главное правило: `handGrip` героя — ОДИН на ВСЕ предметы в правой руке** (кирка, топор, меч, лук, факел…). Его нельзя подгонять под один предмет — сломаются остальные. Под каждый предмет отдельно настраивается только `hold` в его `item.json`.

**Системы координат (без них ничего не подобрать):**
- Предмет (`model.glb`): начало координат = точка хвата, **+Y = от рукояти к головке** (кирка/топор: голова на +Y, лезвие на +X; лук: вертикален по Y, пузо дуги на +X, длина ±0.57 м).
- `handGrip.position` — метры в системе кости `RightHand`; `handGrip.rotation` — Euler `XYZ` (как three.js) кости-хозяина.
- `item.json → hold.<ключ>.rotation/position` — поворот предмета ВНУТРИ, до `handGrip`. Ключ = `itemHoldKey` героя (если задан), иначе id класса (`archer`/`mage`). **Для нового героя с другим ригом обязательно добавь его ключ в `hold` КАЖДОГО лука/посоха** (иначе подхватится поза от чужой кисти — лук ляжет криво). Ось кисти у каждого рига своя: числа с другого героя копировать нельзя.
- Мир модели: +Y вверх, +Z вперёд (нос/носок смотрит +Z); `facingOffset` в игре поворачивает целиком.

**Порядок (всё считается/рисуется инструментами, не «на глаз»):**
1. Пальцы: `gripFingers` — умеренный сгиб вокруг цилиндра (см. §6.1; кулак из клипа бокса — слишком сжатый, но годится, если древко видно в рендере внутри пальцев). Без пальцев-костей — способ B (§6.2).
2. Хват инструмента: `python3 temp_work/rig/tools/grip_solve.py model.glb fingers.json "[0,0,0]" <tilt°> "[0,-1,0]"` — ось древка = ряд костяшек (Index1→Pinky1) в системе кисти, знак выбирается так, чтобы голова шла вперёд; `tilt` (≈30) опускает голову (0 = вверх ≈24°, 30 = почти горизонтально вперёд). Выдаёт `handGrip.rotation`. `handGrip.position` = полость кулака (для Meshy-рига ≈ `[-0.026, 0.085, -0.005]`; уточнить рендером, ±1 см).
3. Рендер-проверка: `python3 temp_work/rig/tools/tool_grip_render.py model.glb content/items/<предмет>/model.glb out.png "[pos]" "[rot]" [--hold "[rx,ry,rz]"] --fingers fingers.json` — 3 панели (кисть спереди/сбоку, всё тело сбоку). **Критерий «хорошо»:** древко проходит ВНУТРИ пальцев, голова впереди (не вниз, не в ногу, не за спину), лезвие кирки/топора вниз/вбок. «Плохо»: предмет висит вертикально голова вниз у ноги или лежит за тыльной стороной кисти.
4. Лук: поза в покое — вертикально у бедра, как у остальных героев. Чтобы лук встал в мире так же, как у эталона (Arissa), посчитай `hold.<ключ>.rotation` для нового героя: `D = R_hand(эталон) · handGrip(эталон) · hold(эталон)`, `hold(новый) = (R_hand(новый) · handGrip(новый))⁻¹ · D` (`temp_work/rig/tools/bow_hold_solve.py ref.glb "[handGrip эталона]" "[hold эталона]" new.glb "[handGrip нового]" fingers.json`). Диагональный лук (≈50°) проходит сквозь бедро — не использовать.
5. **Деформация кисти при выстреле (Emerald Ranger, 2026-11-23).** Оверлей `applyBowOverlay` насильно ставит лук вертикально через запястье. Если хват лука в покое (вертикаль у бедра) перпендикулярен оси кулака, при поднятой руке запястье надо согнуть ~90° — кисть «ломается», сетка тянется. Лечение: `bowDrawHold` героя = поза лука в кисти, при которой после подъёма руки лук вертикален без изгиба: `P = поворот на 94° вокруг боковой оси (вперёд→вверх)`, `W = [X назад, Y вверх, Z]`, `bowDrawHold = (R_hand·handGrip)⁻¹ · P⁻¹ · W` (код: `character.js applyBowOverlay`, лук плавно поворачивается в кисти вместе с подъёмом руки, `restoreOverlay` возвращает). Проверка: поворот между `hold` покоя и `bowDrawHold` ≈ 90–95° — это и есть изгиб, который снимается.  
   Натяжение в бою — `applyBowOverlay` (`character.js`), только во время `swing`; параметры героя: `bowPullKeys` (угол оттяжки левой руки), `bowDrawToFace` (левое предплечье тянется к голове). В покое оверлей не работает — поза в покое целиком из `handGrip` + `hold`.
6. После правки `item.json` и `characters.js`: `python3 temp_work/build_assets.py`, поднять `?v=` в `Avelora.html`, `CACHE_NAME` в `js/sw.js`; в игре проверить: покой с киркой/топором/луком, бег, удар, выстрел.

## 7. Верхом (поза и посадка)

- `character.js applyMountPose`: направления сегментов в системе всадника `[вперёд, наружу, вверх]` для бедра, голени, стопы, плеча, предплечья + наклон корпуса (`lean`, `gallopLean`). Ключи `riderPose` (в overrides героя или в `skill.json` маунта) перекрывают `RIDER_POSE`. Руки не трогаются во время каста.
- Платье/длинный халат: бёдра ближе друг к другу, колени вперёд (`thigh [0.70,0.52,-0.52]`), иначе подол рвётся (Чародейка). Руки: у героев с коротким предплечьем опускать ниже, чтобы кисти были на высоте поводьев.
- Посадка (`mount.js calibrateSeat`): таз всадника = кость `Hips` ставится в точку на хребте маунта (`rideHeight`, `seatForward` из `skill.json`); кости маунта `spine_0/1/2`. У скелетов с другой высотой таза (Meshy, у Чародейки на 11 см ниже, чем у Мага) сидит иначе — у героя нет параметра смещения посадки (идея `seatLift`, не реализована; если нужно, добавить в `calibrateSeat`).
- Проверять верхом: волк, саблезуб (разные седла); ноги не в животном, кисти над холкой, посох поперёк.

## 10. Подводные камни (все уже наступали)

- `temp_work/` не в git: скрипты и модели хранить там, итог — в проектном документе и здесь.
- Windows/Linux: в `git status` десятки «изменённых» файлов — это только CRLF/LF; сравнивать `git diff --ignore-cr-at-eol`. Удаление файлов на устройстве пользователя требует его разрешения (`rm` → «Operation not permitted»).
- GLTFLoader (three r128) очищает имена узлов: `mixamorig:RightHand` → `mixamorigRightHand`; в коде снимают префикс регулярным выражением.
- Не повторять: хват «на глаз» без рендера; перенос кватернионов пальцев между разными моделями; сжатие кулака до «нет полости» (посох будет снаружи); запись `staffGrip` без проверки стороны (посох позади кисти = «рука загнута в другую сторону»); подбор по виду сзади/спереди без вида сбоку.
- Если у героя нет костей пальцев — не пытаться «сделать риг пальцев»: morph-target (§6.2) проще и не ломает остальное.
- Маунт с другой посадкой (Meshy-герой) и непропорциональный скелет — сначала проверить измерения (§4), а не гонять `riderPose`.

- **handGrip под один предмет** (Emerald Ranger): подогнали под лук — кирка и топор повисли вертикально головкой вниз; `handGrip` общий для всех предметов (§6.4).
- **Нет `hold.<ключ героя>` в луках**: взялась поза от кисти другого рига, лук лёг горизонтально (§6.4).
- **Хват «по виду в игре»**: правки без рендера цилиндра/предмета через кисть дают часы итераций; всегда `tool_grip_render.py` до показа пользователю (§6.4).

- **Авториг:** `json.dump` с `numpy.float32` падает (приводить к `float`); в `write_glb` не называть переменную `path` (затирается путь вывода); `--arm-out` подбирается под каждый меш (воин `Idle:8:16`, Forest Sentinel без него: перенос поправки с одной модели на другую разводит руки); `locked` в `genders` блокирует создание и показывает «СКОРО», у `locked`-варианта `overrides` для слота не нужны.

## 11. Навыки класса: мана, `byClass`, навыки воина

**Мана по классам** (`js/config/progression.js → classes.<id>`): `noMana: true` (воин, лучник) → `hero.maxMana = 0`, `skillManaCost = 0`, зелий маны нет, полоска серая без цифр (`.mana-bar.no-mana`, `hero.renderBars`). Маг без флага — как раньше. Навыки этих классов ограничены только кулдауном.

**Общий навык, разные цифры** (`skill.json → byClass`): `"byClass": { "archer": { "cooldown": 5, "damage": {...}, "description": "...", "mana": 0 } }` — для героя этого класса `skills.get(id)` отдаёт копию с перекрытыми полями (остальное наследуется). Рост урона от характеристики: `statByClass` (`{ "archer": "dex" }`), иначе `stat`, иначе `damageStat` по типу урона (`progression.js`; физический по умолчанию `dex`, у воина навыки с `stat: "str"`).

**Типы навыков** (`js/skills.js`): `projectile`, `strike`, `rain`, `nova`, `blink`, `buff`, `teleport`, `mount` + новые `melee` (удар по цели в ближнем бою, `range`, `castTime` = замах) и `charge` (рывок к цели: проверка пути по `pathfinder`, урон + `stun` в конце, `speed`, `stopDistance`). Урон воинских навыков: `weaponMult` × удар оружия × `meleeMult`, `damage` = нижняя планка (`skills.rollSkillDamage`). Бафф: `buff.damageMult` (множитель урона героя), `buff.damageTaken` (0.85 = −15 % получаемого, `hero.absorbDamage`). У `nova` поле `anim: "attack"` = взмах оружием вместо каста; оглушение берётся из `stun`.

**Воин** (`content/characters/warrior/skills.json`): `power_strike` ур.1 (кд 6), `charge` ур.3 (9), `war_cry` ур.4 (45, +20 % урона / −15 % входящего, 20 с), `whirlwind` ур.6 (10, радиус 4.5), `ground_slam` ур.8 (18, радиус 6, оглушение 1.5 с). Иконки сейчас заглушки (`temp_work/gen_warrior_skill_icons.py`), под замену на нарисованные (`content/skills/<id>/icon.png` 128×128 + `python3 temp_work/build_assets.py`).

**Лучник**: `arrow` без маны; `fire_arrow` для лучника через `byClass` (кд 5 с, 36–46, ловкость), у мага без изменений.
